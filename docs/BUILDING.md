# Building

The patch is a set of addons under `addons/`, one per mod, built into
`a3bal_<mod>.pbo` files by [HEMTT](https://hemtt.dev). `addons/main` only holds
the name and version. The other configs are generated by the pipeline
(`tools/a3bal.py release`); don't edit them by hand, or the provenance in
`release.json` stops matching.

## Install HEMTT

Download `windows-x64.zip` (or the Linux build) from the
[HEMTT releases](https://github.com/BrettMayson/HEMTT/releases) and put
`hemtt.exe` on your PATH. The project was tested with HEMTT 1.22.0.

Arma 3 Tools are optional. Without them HEMTT prints a `BBW1` warning and still
builds; nothing here needs binarizing beyond the configs, which HEMTT does itself.

## Build

```powershell
hemtt build
```

Output: `.hemttout/build/addons/a3bal_*.pbo` (about 130 KB together), plus
`mod.cpp`. Add `.hemttout/build` as a local mod in the launcher to try it. Each
mod's addon loads only when that mod is loaded.

Expected diagnostics:

- `L-C12 Math could be unquoted`: a few classes keep an old armor value that the
  mod writes as `"22+ 3"`. The patch writes it back exactly as the mod did.
- `L-C14 unused external classes`: parent classes declared so each file finds the
  right parents. Harmless.

## Release and sign

```powershell
hemtt release
```

This builds, signs every PBO and zips the mod into `releases/`. HEMTT generates a
signing key for the version and puts the `.bikey` in `.hemttout/release/keys/`.
Put that `.bikey` in the server's `keys` folder. Players load the signed folder
from the zip.

To keep one key across versions, create a private key once and keep it out of
git (`.gitignore` already excludes `*.biprivatekey` and `.hemttprivatekey`). See
HEMTT's signing documentation for `.hemttprivatekey`.

To release a new version, bump `addons/main/script_version.hpp` first.

## Without HEMTT

`tools/build_release.py` packs uncompressed, unsigned PBOs with text configs, the
same format the test pilot uses:

```powershell
cd tools
python build_release.py validation/session --pilot balance-pilot --out release
```

That writes `tools/release/@A3Balance`. Sign it with Arma 3 Tools' DSSignFile if
the server checks signatures.

## About the configs

Each `addons/<mod>/config.cpp` is byte for byte the config the test pilot
loaded. Its `CfgPatches` entry carries `a3bal_hash`, a hash of the rest of the
file, which the in-game check compares. `release.json` records the pilot build
ID and every config's hash.

HEMTT binarizes each config into `config.bin`. To check one, extract it
(`hemtt utils pbo extract .hemttout/build/addons/a3bal_sns.pbo config.bin`),
derapify it (`hemtt utils config derapify config.bin`) and compare. For this
build all 18 matched their sources.

`python tools/predict_rebinds.py addons/*/config.cpp` reads the configs the way
the engine does and lists any class whose parent they would change. It must
print 0 for every file. It needs the full-modset capture in
`tools/validation/remaining/full`. See
[HOW_IT_WORKS.md](HOW_IT_WORKS.md#parent-classes).
